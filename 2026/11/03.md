## わかったこと
#### Gitの三層構造
- Gitは、ワークツリー（作業しているファイル）、インデックス、リポジトリ(HEAD)  という三層があり、変更からコミットまでは、どこかに属している。

リポジトリ（HEAD）
↑
↓
インデックス
↑
↓
ワークツリー 
#### reset コマンド
- 上記の三層構造を意識すると、resetコマンドがわかりやすい。
- git reset --soft ・・・HEADが見るコミットを変更する
- git reset --mixed (git resetの標準)・・・インデックスがHEADの内容に書き換えられる
- git reset --hard・・・インデックスとワークツリーがHEADの内容に書き換えられる

#### stash
- stash 変更を一時的にstash領域に保存される
- いつstashが必要なのか。→ ファイルを変更中にブランチを切り替える時。ファイル変更をして、branchを切り替えようとするとエラーになる。
branchを切り替える時は、ワークツリーをHEADコミットの内容に書き換えるため、変更があるとoverwrittenされることになるのでGitがエラーにする。

### git reflog
- コミットやブランチの状態などを一覧で確認することができる。

### git add -p
- Gitは基本的に１ファイル単位でコミットまで行うが、addコマンドに -pを付与することで、ファイル内の行単位（ハンク）でステージングとコミットを分けることができる。変更していない箇所を挟んで、変更箇所があると、その２つを別コミットに分けることができる。
